# workflow.md — Michelle Lim / Flint

## Before drafting: ask these questions

**Platform?** LinkedIn, X tweet, or X Article. Different voice, different structure, different length. If the brief doesn't specify, ask before writing a word.

**Monday or Friday/Sunday?** Monday = product, conversion, bottom of funnel. Friday/Sunday = personal, lighter, no product push. The answer changes the angle entirely.

**Does the brief have a credibility marker?** A number, a named person, a specific moment. If none exists, go back to the source and find one before drafting.

**Is this from an interview or talk?** Pull her actual arguments, not a generalized summary of the topic. "Can you change this to be actual points I made" is the most common feedback on this type of post.

**Has this topic been covered before?** If yes, what's the new angle? Repackaging isn't content. If there's no answer, the post isn't ready.

---

## Drafting: run in this order

1. Pick an opening structure from patterns.md. Default to scene-first or contrast-first.
2. Check the hook has a credibility marker in the first two lines: a number, a named person, or a specific moment. If missing, the hook is dead regardless of what follows.
3. Check that the hook matches what the body delivers. If the hook promises "here's exactly how we set ours up," the body must deliver the full setup, configuration, and use cases. Not an installation step. Not a starting point the reader has to finish themselves.
4. Pull content from Michelle's real experience: something she did, said, attended, or built. No generic industry takes.
5. Replace every generic noun with its specific version. A number, a name, a company. Both if available.
6. If a photo is attached, write at least one line that narrates it. Name the people. Say what they're doing. A photo dropped in without a written tie-in is a broken post even if the prose is fine.
7. Write the closing line. Test it: does it distinguish or describe? Could it appear in any competitor's post? If yes, rewrite.
8. If both LinkedIn and X are needed, write the X version by subtracting. Delete hedges, CTAs, qualifiers, and setup. Start with the contrarian thesis. No caveats.

## AI-ism audit (run before the pre-submit checklist)

After drafting, scan the draft for AI patterns against `_system/forbidden/` files.

Two modes — choose one based on where the draft is:

**Detect mode:** use when the draft feels close. Flags every AI-ism with the offending text quoted. No rewriting. You decide what to fix.

**Rewrite mode:** use when the draft needs a full clean. Flags, rewrites, then runs a second-pass audit on the rewritten version before returning it.

`mechanics.md` (the forbidden files) covers banned words while drafting. The audit catches what survives: clusters, density, and patterns the banned list doesn't reach.

## Pre-submit checklist

Run this before sending. Fix any failure before submitting.

- [ ] Zero em dashes anywhere in the draft
- [ ] No "not X but Y" or "not because X but because Y" constructions
- [ ] No words from the banned list in `_system/forbidden/phrases.md`
- [ ] No closing sentence that performs humility
- [ ] No "it sounds X. It's not." reversals
- [ ] No closing definition structured as "X is the Y"
- [ ] No sentence that could appear in a McKinsey deck or a LinkedIn thought leader post
- [ ] No sentence that thesis-states before the scene has done the work
- [ ] Photo attached? At least one line in the body narrates it with named people.
- [ ] Hook makes a promise? Check the body actually delivers on that exact promise. "Here's exactly how" requires the full how.
- [ ] Educational post or carousel? Apply the work-gap test: how much effort sits between reading and doing? If it's more than one step, it's not ready.
- [ ] X Article? Header image flagged with Michelle. Cannot be scheduled.
- [ ] Read the last line out loud. Does it sound like something Michelle would say to a friend? If it sounds assembled, cut or rewrite it as a plain statement.
- [ ] Read the whole draft out loud. Any sentence that makes you pause because it sounds written rather than spoken: rewrite it.

## Edge cases

**Brief is open-ended:** Offer 2-3 options with different angles. Not different wordings of the same idea. Different protagonists, different proof, different frames.

**Brief is too thin:** Ask one question before drafting. One, not five.

**The angle is wrong:** Say so. Propose a different post. A different protagonist, a different theme, a different proof point. Don't trim a draft that's pointed at the wrong story.

**Hook makes a strong claim:** The next sentence must prove it. If there's no proof, change the hook. Don't soften it.

**Customer quote is generic:** Push for specificity. What was the unit of work? What was the verb? What was the count? "Done in minutes" loses to "drop in a CSV and spin up hundreds of tailored pages" every time.

**Launch or fundraising week:** Post twice daily including weekends. Skipping weekends kills momentum.

**Involving another person:** Flag Michelle before publishing. She needs their approval.

**Draft feels generic or vague, especially a testimonial/case-study post:** Don't paper over it with abstract reasoning ("without having to think about design, brand, or engineering") or a generic thesis statement ("that's what X should feel like"). Go get the real specific — ask Viktor (Flint's internal AI knowledge Slack bot) for the mechanism, the number, or the named source if it's not already in `flint/context/first-party.md`.
